네 문제에는 원인이 둘 겹쳐 있다.

1. **기록 지점이 특정 표면에 묶여 있다.** 근거는 kit의 실행 경로에, 관찰은 aelix의 `bash`에, 맥락 주입은 aelix의 hook에 걸려 있다. 에이전트가 다른 도구를 쓰거나
   호스트가 바뀌면 같은 일이 기록되지 않는다.
2. **근거와 참조의 단위가 표 형식 파일과 로컬 경로다.** 표가 아닌 자료(도구의 결과, 문서, 이미지)는 근거로 가리킬 방법이 없고, 본문이 대상을 가리키는 가장 쉬운
   방법이 절대 경로다.

실험(#196)에서 확인한 것은 다음과 같다. 모두 aelix 0.1.0b2, macOS에서의 값이다.

- aelix의 `tool_result` hook은 다른 확장과 MCP 서버의 도구에도 불리고 결과 블록과 `details`가 실린다. `tool_execution_end` hook에는 결과가 없다.
  확장이 보는 결과는 앞서 로드된 확장이 고친 것까지이고, 뒤에 로드된 확장이 덧붙인 것은 보이지 않는다.
- bash·write·edit가 든 메시지는 호출을 하나씩 실행한다. 함께 실행되는 것은 read·grep·find·ls와 다른 확장·MCP 도구끼리뿐이다.
- 다른 확장의 도구가 프로젝트의 `data/`에 쓴 파일은 main에서 어떤 기록에도 남지 않는다.
- 비용: 호출 하나에 로그 한 줄과 결과 보관으로 약 0.5 ms가 더 들고(결과 1–14 KB), 파일 1,000개인 프로젝트를 한 번 훑는 데 약 9 ms, 10,000개에 약 73 ms였다.
- 실험 branch에서 aelix 통합 시험 1,142개와 저장소 전체 시험 3,483개가 통과했다(`4a6d461`). 실제 모델로 돌린 세션, 실제 MCP 서버, 별도 프로세스의 세션,
  Windows는 돌려 보지 않았다.

호스트가 결정 1의 사건을 줄 수 있는지는 다음까지 확인했다. 결정이 아니라 읽은 것이고, 호스트별 대응은 #192가 실제 버전으로 확인한다.

| 호스트 | 확인한 방법 | 읽은 것 |
|---|---|---|
| aelix 0.1.0b2 | 코드를 읽고 실험의 시험으로 돌림 | `before_agent_start`·`context`·`tool_call`·`tool_result`·`agent_end`·`session_compact` hook이 여섯 사건을 준다. 시스템 프롬프트, 메시지, 도구 결과 뒤의 글을 모두 전할 수 있다 |
| Claude Code | [공식 hooks 문서](https://code.claude.com/docs/en/hooks)를 2026-11-18에 읽음. 돌려 보지 않음 | `SessionStart`·`UserPromptSubmit`·`PreToolUse`·`PostToolUse`·`Stop`이 있고, `PostToolUse`의 입력에 도구의 인자와 결과가 있으며 MCP 도구와 하위 에이전트의 호출에도 불린다고 적혀 있다. 압축 뒤에는 `SessionStart`가 다시 불려 맥락을 넣을 수 있다고 적혀 있다. 추가한 맥락은 시스템 프롬프트가 아니라 대화에 들어간다. `PostToolUse`는 성공한 호출의 사건이고 실패는 다른 사건이다. `PreToolUse`와 `PostToolUse`를 같은 식별자로 짝짓는다는 문장은 찾지 못했다 |
| Codex와 그 밖 | 확인하지 않음 | — |

## 결정

### 1. 경계 사건: 호스트가 알리고 kit이 판단한다

세션에서 일어나는 일을 kit은 **경계 사건**(boundary event)으로만 안다. 호스트 어댑터는 사건을 kit에 옮기고, 무엇을 남기고 무엇을 알릴지는 kit이 정한다.

| 사건 | 언제 | 호스트가 주는 것 | kit이 하는 일 |
|---|---|---|---|
| 세션 시작 | 세션이 시작되거나 이어질 때 | 세션 식별자, 작업 디렉터리 | 프로젝트를 찾고, 세션 동안 바뀌지 않는 맥락과 시작 시점의 상태를 돌려준다 |
| 프롬프트 | 사람이 프롬프트를 보낼 때마다 | 세션 식별자 | 지난 프롬프트 이후의 변경분(다른 세션·사람의 기록, 파일 변경)을 돌려준다 |
| 호출의 시작(선택) | 도구 호출 직전 | 호출 식별자, 도구 이름, 인자 | 실행 창의 시작을 잡는다. `bash`이면 ADR-0015의 앞 상태를 본다 |
| 호출의 끝 | 도구 호출이 끝나 결과가 정해진 뒤 | 호출 식별자, 도구 이름, 인자, 결과 블록, 도구가 준 구조화된 결과, 오류 여부 | 세션 로그에 남기고, 결과를 보관하고, `bash`이면 ADR-0015의 뒤 상태를 보고, 결과 뒤에 붙일 글이 있으면 돌려준다 |
| 에이전트 정지 | 에이전트가 응답을 마쳤을 때 | 세션 식별자 | 파일 상태를 대조하고 Workspace를 갱신한다. 호스트를 기다리게 하지 않는다 |
| 대화 압축 | 호스트가 대화를 줄였을 때 | 세션 식별자 | 시작 시점의 상태를 다시 주도록 표시한다 |

- **kit의 진입점은 하나다.** 사건마다 kit의 같은 함수를 부른다. 프로세스 안에서 kit을 로드하는 호스트(aelix)는 함수를 직접 부르고, 명령을 실행하는 hook만 있는
  호스트는 같은 함수를 부르는 kit CLI에 사건을 JSON으로 넘긴다. 사건의 형식과 CLI의 이름은 호스트 어댑터 ADR이 정한다.
- **어댑터는 옮기기만 한다.** 호스트의 사건을 위 사건으로 바꾸고, kit이 돌려준 것을 호스트의 방식으로 전달한다. 프로젝트의 파일을 직접 쓰지 않고,
  무엇이 분석 단계인지나 무엇을 알릴지를 판정하지 않는다. 그래서 같은 사건은 어느 호스트에서 와도 같은 기록이 된다
  ([아키텍처](../ARCHITECTURE.md) 4절: "호스트·화면마다 같은 규칙을 다시 구현하지 않는다").
- **kit이 호스트에 돌려주는 것은 세 가지뿐이다**: 세션 동안 바뀌지 않는 맥락, 그 시점에 모델에게 전할 글, 도구 결과 뒤에 붙일 글. 호스트가 그 가운데
  전달할 방법이 없는 것은 전달하지 않고, 어댑터의 문서가 그 차이를 적는다.
- **사건을 다 주지 못하는 호스트도 받는다.** 호출의 시작이 없으면 함께 실행된 호출을 알 수 없고 ADR-0015의 앞 상태가 없다. 호출의 끝이 없으면 세션 로그와
  결과 보관이 없다. 프롬프트와 에이전트 정지만 있어도 파일 상태의 대조는 동작한다. 사건이 하나도 없으면 지금의 CLI·SDK 경로다.
- **프로세스 사이의 통로는 환경의 상속뿐이다.** 하위 에이전트처럼 다른 프로세스에서 도는 세션은 자기 어댑터가 있으면 자기 사건을 자기 세션 식별자로 알린다.
  어댑터가 없으면 그 프로세스가 한 일은 부모 세션의 그 도구 호출의 실행 창과 파일 상태의 대조로만 보인다.
- **사람의 `!` 명령은 감싸지 않는다**(ADR-0015의 결정과 이유를 유지). 그 명령이 남긴 파일 변경은 파일 상태의 대조가 "어느 호출의 밖에서 바뀜"으로 잡는다.

### 2. 세션 로그와 journal

세션에서 본 것(호출, 결과의 해시, 대조의 결과)은 **세션 로그**에 남긴다. 세션 로그는 보조 로그다.

- journal의 줄이 아니다. seq가 없고, 공통 reader·출처 추적·Timeline·공유본이 읽지 않는다. 지워도 journal이 말하는 것은 달라지지 않는다.
- 줄마다 형식의 이름과 판을 갖고, 읽는 쪽은 모르는 형식의 줄을 지나친다. 전환(migration)의 대상이 아니다.
- 프로젝트의 이력이 아니다. 그 기계의 그 세션이 본 것이므로 기본으로 git에서 제외한다(OQ2). 실험(#196)은 세션 로그를 `telemetry.jsonl` 옆에 두어
  새 템플릿에서 git이 추적했다. 이 결정은 그와 다르다.

journal에 올라가는 길은 셋이고, 모두 지금 있는 기록 경로다.

1. **기록이 근거로 인용할 때.** 발견·결정 같은 기록의 참조가 호출이나 등록된 원천을 가리킨다. 저자가 인용한 것과 kit이 대조로 찾은 것을 `basis`로 구별한다(OQ6).
2. **데이터로 가져올 때.** 보관된 결과나 파일을 가져오기가 받아 지금의 가져오기 기록을 남긴다.
3. **관찰된 활동.** ADR-0015 그대로다.

그래서 이 ADR은 새 기록 종류(kind)를 더하지 않는다. 새 참조 종류는 [ADR-0006](0006-common-record-contract.md) 1절 2항(새 kind·type·relation만 더함)과
3항(쓰기 규칙을 더하는 PR의 `min_writer_version`)을 따르며 참조 ADR이 정한다. journal 줄이 늘지 않으므로 [ADR-0014](0014-publication-record-contract.md) 결정 2의
`content_seq` 집합도 바꾸지 않는다.

모든 호출을 journal에 남기지 않는 이유는 ADR-0015가 "모든 bash 호출을 기록"을 기각한 이유와 같다. 기록할 사실이 없는 호출이 Timeline을 덮고, 추적되는 이력에
세션의 세부가 쌓인다.

### 3. 근거의 단위: 해시로 가리키는 바이트

근거가 될 수 있는 것의 단위는 표가 아니라 **바이트와 그 sha256, 매체 종류, 그 안의 위치**다. 도구의 결과, 텍스트·문서·이미지 파일, 표 형식 파일이 같은 단위다.

보관의 수명은 셋이다.

| 수명 | 무엇 | 어디에, 얼마나 |
|---|---|---|
| 임시 보관 | 호출의 끝에서 본 결과 | 프로젝트의 캐시. git이 무시하고, 결과 하나의 크기·전체 크기·기간에 상한이 있으며 넘으면 오래된 것부터 지운다 |
| 남김 | 기록의 근거로 쓰인 결과 | 프로젝트의 상태 디렉터리. 기본으로 git에서 제외하고 제외를 풀지는 소유자가 정한다. 크기 상한을 넘거나 가림 규칙(ADR-0015 결정 5의 규칙)이 자격 증명을 찾은 결과는 남기지 않는다 |
| 가져옴 | 데이터셋, 그리고 변환 없이 등록한 원천 | 지금의 `data/`와 그 git 규칙 |

- **원천**(source)은 표로 바꾸지 않고 파일의 목록과 해시로 등록한 입력이다. 형식은 #193의 파일럿 뒤에 정한다.
- **위치 지정자**(locator)는 근거 안의 자리다: 문서의 쪽, 텍스트의 줄 범위, 이미지의 영역, 표의 행. 문법은 참조 ADR이 정한다.
- 해시는 그 바이트가 있었다는 사실만 말한다. [용어집](../TERMINOLOGY-AND-LANGUAGE.md) 5절대로, 참조가 있다고 자료의 보존이나 결론의 검토가 끝난 것은 아니다.
  임시 보관이 지워지면 참조는 해시와 크기만 가리키며, 그 상태를 "보존되지 않음"으로 보인다.
- 공유본에는 임시 보관과 남긴 결과를 넣지 않는다. 그 대상은 지금의 `not_included` 표시다(종류와 사유만, 이름·ID 없음).

ADR-0015는 "출력 저장"을 "데이터 행·개인 정보가 들고 크다"는 이유로 기각했다. 그 기각은 git이 추적하는 journal과 `.analytics/observed/`에 대한 것이다.
이 결정의 보관은 기본으로 git 밖에 있고 상한이 있으며, 남기는 것은 근거로 쓰인 결과뿐이다. 보관을 끄면 해시만 남는다(OQ3).

### 4. 기호 참조

기록과 Report 본문이 프로젝트의 대상을 가리킬 때는 **기호 참조**를 쓴다. 기호 참조는 대상의 종류와 식별자, 필요하면 위치 지정자로 이루어지고 환경 값을 담지 않는다.

- 지금 기록이 받는 이름(run ID, `e<seq>`, `스크립트::시각화`, 데이터셋 이름)은 그대로 기호 참조다. 더하는 것은 호출, 원천, 프로젝트 안의 파일을 가리키는 참조다.
- 해석은 표시하거나 게시하는 쪽이 한다. Workspace는 로컬의 대상으로, 공유본은 포함한 대상이나 `not_included` 표시로 잇는다.
- 절대 경로를 쓴 본문도 계속 저장된다([ADR-0013](0013-report-storage-and-collections.md): 저장한 바이트를 고치지 않고, 파일 종류를 가려 받지 않는다).
  기호 참조는 강제가 아니라 누출 없이 쓸 수 있는 길이다.
- 문법과 새 참조 종류는 참조 ADR이 정한다. ADR-0006의 참조 `type`은 닫힌 목록이므로 기록 형식 변경이다.

### 5. 네 자리의 검사: 알리고, 게시만 막는다

세션이 프로젝트에 남기는 자리는 넷이다: 파일, 기록, 저장한 Report, 공유본. 자리마다 결정적인(모델을 부르지 않는) 검사를 두고, 결과를 그 자리에서 알린다.
막는 것은 지금처럼 공유 build의 누출 검사뿐이다.

| 자리 | 검사 | 결과가 가는 곳 |
|---|---|---|
| 파일 | **상태 대조**: 지난번에 본 상태와 비교해, run·가져오기·관찰된 활동이 말하지 않는 변경을 찾고 세션 로그의 호출에 대조한다. 그 파일을 가리킨 호출, 실행 창이 수정 시각을 포함하는 호출들, 어느 호출의 밖 가운데 하나다 | 세션 로그, 다음 프롬프트의 변경분 |
| 기록 | **수치 대조**: 기록의 글에 적힌 수치를 그 세션의 보관된 결과에서 찾는다 | 세션 로그, 기록을 쓴 요청의 답(OQ4), 기록의 참조(OQ6) |
| 저장한 Report | **저장 시점의 검사**: 형식을 판정하고, 공유 범위와 무관하게 판정되는 누출(환경 값)을 찾아 모두 알린다. 저장은 거절하지 않는다 | 저장한 요청의 답 |
| 공유본 | 지금의 누출 검사. 보장은 그대로다: 환경 값과 제외한 내용이 게시본에 남지 않는다 | build의 오류 |

- **이 검사들은 서로 다른 신호이고, 지금의 상태들과도 합치지 않는다.** "수치가 결과에서 보임"은 실행 성공·근거 연결·재실행 비교·분석 검사·결론 검토 가운데 어느 것도
  아니다([용어집](../TERMINOLOGY-AND-LANGUAGE.md) 6절). 화면에서 보여 주는 방식은 후보를 비교해 소유자가 고른다(#188과 같은 방식).
- **공유가 막혔을 때 고치는 길은 파생 버전이다.** kit은 저장된 Report 버전에서 새 버전을 만들 수 있다: 환경 값을 기호 참조로 바꾸고, 범위 밖 대상을 가리키는
  참조를 자리표시자로 바꾼 버전이다. 원본 버전은 그대로 두고, 파생 버전은 원본과 한 변환을 기록하며 원본과 같다고 표시하지 않는다
  ([보고서 산출물 설계](../REPORT-ARTIFACTS.md)의 "가공한 공유용 파일"). build는 지금처럼 고른 버전의 바이트를 그대로 담고 같은 검사를 한다.
  build가 본문을 가리거나 고치지 않는다는 계약([계약 D2](../CONTRACTS.md#d2-공유-범위의-무쓰기-미리보기-kit-0230))은 그대로다.
  파생 버전의 기록 형식, kit이 저장할 때 만들지 요청할 때 만들지, 어떤 변환을 할지는 #187의 ADR이 정한다.
- **검사 강도를 독자에 따라 낮추는 안은 이 ADR에 없다.** 보장을 바꾸는 결정이고 #187의 소유자 결정으로 남는다.

### 6. 프롬프트와 도구 표면

- 시스템 프롬프트에 붙이는 부분은 세션 동안 바이트가 같아야 한다. 기록에 따라 바뀌는 것(시작 시점의 상태, 변경분)은 메시지로 전한다.
  모델 제공자의 캐시는 요청의 앞부분이 같아야 맞고, 시스템 프롬프트는 여러 확장이 나눠 쓰기 때문이다.
- 이 ADR의 기능은 상시 도구를 더하지 않는다([제품 방향](../PRODUCT.md)의 설계 경계: 기능 확장이 상시 도구 수 증가를 뜻하지 않게 한다).
  알림은 기존 도구의 답과 프롬프트의 변경분에 붙고, 읽기는 기존 조회와 CLI에 붙는다.
- 호스트가 달라도 같은 규칙이다. 세션 동안 바뀌지 않는 맥락과 변경분을 호스트의 어느 자리에 넣을지는 어댑터가 정한다.

### 7. ADR-0015의 개정

채택하면 ADR-0015 결정 1의 "범위 밖" 문단을 다음 뜻으로 고친다. `observed_activity`의 뜻·조건·형식과 나머지 결정은 그대로다.

> 범위 밖: 관찰된 활동으로 기록하는 것은 aelix의 `bash` 호출뿐이다. write·edit 도구의 직접 쓰기와 다른 확장·MCP 도구의 호출은 관찰된 활동으로 기록하지 않고,
> [ADR-0016](0016-session-boundary-model.md)의 경계 사건으로 보아 세션 로그에 남기며 그 변경은 파일 상태의 대조가 다룬다. 사람의 `!`·`!!` 명령은 감싸지 않는다.
> aelix 밖 호스트는 그 호스트의 어댑터가 사건을 줄 때 같은 세션 로그를 갖는다.

ADR-0015가 기각한 입력 캡처(`sitecustomize`·`PYTHONPATH` 주입)는 이 ADR이 되살리지 않는다. kit이 띄우는 run 안에서 읽은 파일을 형식과 관계없이 남기는 것과,
프로젝트의 venv 안에서 도는 kit 밖 Python을 기록하는 것은 #191이 따로 정한다.

### 8. 주장하지 않는 것

- **완전성**: 사건을 주지 않는 호스트, 어댑터가 없는 프로세스, 프로젝트가 활성화되기 전의 호출, 상한을 넘은 결과와 훑기는 보이지 않는다.
- **인과**: 실행 창이 파일의 수정 시각을 포함한다는 것은 그 호출이 도는 동안 바뀌었다는 뜻이다. 그 호출이 바꿨다는 뜻이 아니다.
- **정확성**: 수치가 결과에서 보였다는 것은 그 수가 거기 있었다는 뜻이다. 같은 숫자의 다른 양일 수 있고, 보이지 않은 수치는 본 수들에서 계산한 값일 수 있다.
- **결과의 동일성**: 세션 로그의 해시는 어댑터가 본 결과의 해시다. 호스트가 그 뒤에 결과를 고치면 모델이 본 것과 다를 수 있다.
- **호스트 사이의 동등성**: 호스트가 주는 사건과 전달할 수 있는 것이 다르면 남는 것도 다르다. 같은 것은 같은 사건이 같은 기록이 된다는 점이다.
- **비밀의 제거**: 가림 규칙은 거부 목록이다. 규칙을 적용했다는 뜻이지 비밀이 남지 않았다는 뜻이 아니다.
- **재현**: 세션 로그와 보관된 결과는 재실행의 대상이 아니다. run의 보장([계약 C2](../CONTRACTS.md#c2-run-runsidrunjson))은 run에만 있다.
- **사람의 직접 분석에 대한 같은 검사**: 호스트 없이 CLI로 일하는 사람의 터미널 출력은 보이지 않는다. 상태 대조는 CLI로 돌릴 수 있고, 수치 대조는 볼 결과가 없다.

| 기호 참조를 강제(경로를 쓴 본문을 거절) | 본문 형식을 강제하지 않는다는 원칙(ADR-0013, 제품 방향의 설계 경계)을 깬다 |

## 결과와 영향

- 관찰의 범위가 "aelix의 bash"에서 "어댑터가 알린 모든 호출"로 넓어지지만 journal은 그만큼 늘지 않는다. 늘어나는 것은 git 밖의 세션 로그와 보관이다.
- 호스트를 더하는 일이 "확장을 다시 만드는 일"에서 "사건을 옮기는 어댑터를 쓰는 일"이 된다. 판단 로직은 kit에 하나다.
- 표가 아닌 자료가 근거의 단위가 되므로, 문서·이미지·도구 결과를 인용한 발견이 근거를 가질 수 있다. 무엇이 실제로 끊기는지는 #193의 파일럿이 본다.
- 공유가 막히는 구조적 원인 둘(본문의 환경 값, 고치는 도움이 없음)에 길이 생긴다. 실제 보고서의 통과율이 얼마나 오르는지는 #187의 기준선으로 잰다.
- 비용: 호출마다 로그 한 줄과 결과 보관(실험에서 호출당 약 0.5 ms), 프롬프트와 에이전트 정지마다 파일 훑기 한 번(파일 1,000개에 약 9 ms), 기록마다 수치 대조.
  프로젝트의 캐시에 결과 바이트가 쌓이고(상한 있음), 명령형 hook을 쓰는 호스트에서는 사건마다 프로세스 하나가 뜬다(재지 않았다).
- 계약 A가 넓어진다: `context`·`session_compact` hook, 모든 도구에 대한 `tool_result` 처리, 이벤트 버스의 채널. 구현 PR이 계약 A와 용어집을 고친다.
- 사람의 직접 분석 경로는 바뀌지 않는다. 호스트가 없으면 세션 로그가 없고, 기록·실행·공유는 지금과 같다.
