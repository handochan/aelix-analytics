# 제품 효과 평가 설계 — 확장이 있을 때와 없을 때

- 상태: **채택(2026-10-31 소유자), 구현 전.** [베타 품질 기준](../BETA-QUALITY-GATES.md) §3의 모델 측정(12과제 × 3회 × 두 모델, 성공률 90%)을
  이 설계의 비교와 판단 규칙으로 바꿨다. 미결정 O1–O5는 13절대로 정했다. 측정은 10절의 단계로 한다.
- 작업: [#24](https://github.com/handochan/aelix-analytics/issues/24) 출시 리허설(B6)의 모델 측정.
- 따르는 결정(2026-10-31 소유자):
  - 같은 작업을 aelix-analytics가 있을 때와 aelix 순정(확장·kit 없음)으로 비교한다.
  - 모델은 상위 gpt-6.1-sol, 하위 Qwen3.8 27B(OpenRouter)다.
  - 판단 규칙과 수치는 측정 전에 정한다.
  - 평가는 분석 판단의 정오보다 제품의 약속(재개·근거·흐름 파악·분석 프로젝트의 사용성)을 재고, 개선할 곳을 찾게 한다.
- 기준 코드: main `644e080`. kit은 출시 후보 0.32.0(`26c28d0`)과 같다.

## 1. 왜 다시 설계하나

제품이 약속하는 것은 [제품 방향](../PRODUCT.md)의 "사용자가 얻어야 하는 것"과 "개선을 판단하는 기준"이다. 핵심은 네 가지다.
- 새 세션에서도 분석을 이어 간다.
- 모든 분석에 근거가 있고, 그 근거로 되돌아갈 수 있다.
- 에이전트가 분석의 흐름(목적·질문·판단과 그 변경)을 파악한다.
- 분석 프로젝트를 하기에 알맞은 사용성을 준다.

같은 문서는 "결론의 참을 자동 인증한다는 뜻은 아니다"라고 적는다.

지금의 측정(§3, 하네스 [#40](../../tools/model_eval_data/README.md))은 정답 대비 절대 성공률 하나를 본다. 2026-10-31의 시범 캠페인
(두 모델 × 64 run, 아래 11절)에서 기본 조건의 자동 채점은 gpt-6.1-sol 21/36, Qwen 17/36이었다. 실패의 상당수는 제품의 약속과 거리가 있었다.
- **답 형식**: 분석은 맞았지만 답에 근거 ID를 적지 않았다(gpt의 근거 검사 실패 9).
- **분석 판단**: 분모·기간·집계 키·주장 판정의 정오가 갈렸다. 모델의 역량이다.
- **정답의 엄격함**: T04는 "4,000자에서 잘렸다"를 요구한다. 그런데 kit은 e74를 읽을 때 잘린 길이도, 잘렸다는 표시도 주지 않는다.

절대 성공률 하나로는 실패가 제품 탓인지 모델 탓인지 가를 수 없고, 제품이 무엇을 더해 주는지도 보이지 않는다.

## 2. 원칙

1. **비교한다.** 같은 모델·데이터·요청 글·제한 시간에서 조건만 바꾼다. 두 조건의 차이가 제품의 효과다.
   채점 기준의 엄격함은 두 조건에 똑같이 걸리므로 비교 결과를 흔들지 않는다.
2. **제품의 약속을 잰다.** 재개, 근거 추적, 판단 이력, 작업 축적, 비용, 분석의 자유도를 잰다(4절).
3. **분석 판단의 정오는 판정 기준이 아니다.** 확장이 판단을 나쁘게 만들지 않는지만 본다(E6).
4. **진단이 결과물이다.** 실패마다 제품 쪽 원인 후보를 자동으로 가리키고 사람이 확정한다(7절).
5. **미리 정한다.** 판단 규칙과 수치는 측정 전에 정한다. 정답이나 채점 규칙을 바꾸면 두 조건 모두 다시 채점한다.
6. **자동 채점은 필요조건이다.** 모델의 자기평가는 쓰지 않는다. `needs_review`는 에이전트의 1차 판단을 표로 내고 사람이 확정한다.

  - 요청 글. 요청 글은 도구 이름을 말하지 않는다.
  - 제한 시간, 작업 루트의 격리, `--no-context-files`, 비밀 검사.

### 정답의 형태

- **상태 사실**(재개·이력): fixture의 기록이나 앞 세션이 남긴 것에서 정해진다.
- **앞 세션 결과의 회수**(Part II): 정답은 두 가지로 정한다.
  - 데이터가 정하는 값. 예: 같은 기간 비교 +20.6%.
  - 앞 세션이 실제로 말하거나 기록한 값.
  - 앞 세션이 그 값을 내지 못했으면 그 체인의 회수 검사는 "해당 없음"이다. 세션 1의 완수는 따로 센다.
- **분석 판단의 정오**: 지금 정답(T07–T10의 값)을 그대로 쓰되 E6에서만 쓴다.

## 7. 진단 — 개선할 곳 찾기

1. **정보 가용성.** 실패한 사실·근거 검사마다, 그 값이나 ID가 그 run에서 모델이 받은 도구 결과(맥락 블록 포함)에 있었는지 본다.
   - 받았는데 답에 없음: 활용 문제다. 모델의 문제이거나, 결과가 길어 묻힌 것이다.
   - 받지 못했지만 확장의 읽기로 얻을 수 있음: 발견 가능성 문제다(도구·설명).
   - 확장의 어떤 읽기로도 얻을 수 없음: 제품의 공백이다. 시범의 T04가 그렇다(e74의 잘린 길이).

   "어떤 읽기로 얻을 수 있나"는 과제마다 kit의 읽기(맥락 블록, 상태, ID 읽기, 검색)를 결정적으로 돌려 미리 표로 적어 두고 그 표로 판정한다.
2. **도구 흐름.**
   - 조건별 도구 호출의 분포
   - A에서 확장을 두고 원시 파일을 읽은 호출과 그때 찾으려던 것
   - 같은 조회의 반복
   - 도구별 오류와 그 인자
3. **비용 분해.** 맥락 블록, 도구 결과, 재시도가 토큰의 어디를 차지하는지 본다.
4. **개선 후보 보고서.** 제품 부품(맥락 블록, 상태, 조회, 기록 도구, Workspace)별로 사례 수와 대표 run을 묶는다.
   소유자가 고른 것을 Issue로 만든다.

## 8. 판단 규칙(사전 등록)

모델마다 같은 과제·같은 반복 번호의 짝으로 A와 V를 비교한다.

| 규칙 | 내용 | 상위 모델 | 하위 모델 |
|---|---|---|---|
| R1 재개 | A의 재개 정확도가 V보다 높고, A가 V보다 낮은 과제가 없다 | 판정 | 판정 |
| R2 근거 | A의 근거 연결률·한계 표시가 V보다 높고, 없는 ID는 A ≤ V | 판정 | 판정 |
| R3 맥락 오류 | A ≤ V | A = 0 | A ≤ V |
| R4 축적 | Part II의 회수율이 A > V, 중복 작업은 A ≤ V | 판정 | 판정 |
| R5 해 없음 | 분석 결과와 자유 분석의 완수가 A ≥ V − (과제당 반복 1회분) | 판정 | 판정 |
| R6 비용 | R1–R4를 만족한 과제에서 A의 토큰 중앙값이 V의 1.2배를 넘으면 이유를 적고 검토한다 | 보고 | 보고 |
| R7 절대 하한 | A의 재개 정확도와 회수율이 2/3 이상 | 판정 | 보고 |

- **통과**: 상위 모델이 R1–R5와 R7을, 하위 모델이 R1–R5를 만족하면 모델 게이트를 통과한다.
- **보류**: 하나라도 만족하지 못하면 출시 보류 사유다. 진단(7절)의 제품 공백을 고친 뒤 다시 잰다.
- **수치**: 2/3, 1.2배, 반복 1회분은 소유자가 측정 전에 확정했다(2026-10-31, O3).

## 9. 규모·비용·시간

- **Part I**: 8과제 × 3회 × 2조건 × 2모델 = 96 run이다.
  - A의 T01–T05·T11(모델마다 18 run)은 시범 run을 새 지표로 다시 채점해 쓸 수 있다.
  - 그래서 새로 도는 것은 60 run이다.
- **Part II**: 3체인 × 3세션 × 3회 × 2조건 × 2모델 = 108 세션이다.
- **토큰**: 시범의 기본 조건과 비슷하거나 1.5배쯤 본다. 시범에서 Qwen의 토큰은 대부분 T12(자유 EDA)였다. run 하나에 비캐시 입력 0.40M, 캐시 입력 4.3M이었다.
  Part II의 C1이 비용의 중심이 된다.
- **시간**:

두 모델 × 64 run을 돌렸다(기본 12과제 × 3회, Q5 제안 조건, Q11 도구 표면, #9 이름 전환 전 비교). 원자료는 이 기기의 run 디렉터리에 있다.

- **채점기 결함**: 중대 오판 검사가 물음표로 끝나는 줄을 모델의 질문으로 보고 건너뛰었다. 그래서 닫힌 질문을 그 질문의 글과 함께 열린 질문으로
  나열한 답(Qwen T01 r1)을 놓쳤다. 고친 뒤 모든 run을 다시 채점했다.
- **휴리스틱 오판**: 중대 오판 검사가 발생한 18 run 가운데 실제 오판은 1이었다. 나머지 17은 부정문, 비교표의 틀린 값 칸, 코드 주석을 잘못 읽은
  것이었다. 그 가운데 14 run은 사람이 오판을 확정하면 성공이 된다. 새 설계는 맥락 오류를 사람이 확정하는 항목으로 두고, 1차 판단을 표로 낸다.

- **비용**: T12가 Qwen 토큰의 대부분을 차지했다.
- **운영**: OpenRouter 크레딧이 떨어져(402) 21 run이 모델 없이 끝났고, 충전한 뒤 다시 돌렸다. 실행 전에 예산을 확인한다.
