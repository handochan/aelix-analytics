## 독자 환경과 브라우저

- **원본 없는 위치**(`tests/test_publication_reader.py`, 세 OS CI): 저장한 사본을 한국어·공백 경로로 옮기고 프로젝트를 지운 뒤 순회한다.
  `file://`과 HTTP 두 단계 하위 경로(`/a/b/<publication_id>/`)로 모든 파일과 페이지의 참조를 따라가고, 모든 요청이 그 하위 경로 안에서 200이다.
  ZIP은 `zipfile`·`unzip`·`ditto -x -k`·`Expand-Archive`로 풀어 바이트와 `--verify`를 대조한다. macOS 로컬은 7 passed다.
- **브라우저 E2E**(`tests/test_publication_browser.py`): 모든 kit 페이지 × `file://`·HTTP에서 사본 밖 요청 0·콘솔 오류 0·이미지와 plotly가 그려진다.
  발견 → 그림 → run → 코드로 갔다가 뒤로 가기로 같은 anchor에 돌아온다. frame sandbox, JS 꺼짐, 파일을 지운 사본의 안내, Report 본문 frame도 본다.
  CI는 Linux 레그의 Chromium이고 Firefox·WebKit은 로컬에서만 돌렸다.

**sandbox·CSP 결정의 측정.** 세 엔진 × `file://`·HTTP에서 iframe sandbox에 아무 값이 없으면 `file://`의 frame이 자기 그림을 불러오지 못했다(세 엔진
모두 "Not allowed to load local resource" 계열). `allow-same-origin`이면 여섯 경우 모두 불러왔다. CSP의 `style-src 'self'`는 plotly의 inline style을
막아 엔진·경로마다 콘솔 오류 24–25건을 냈고, `'unsafe-inline'`을 더한 채택안은 12쪽 모두 문제가 없었다. 이 측정은 `data:` 아이콘을 넣기 전이라
WebKit `file://`에 디렉터리 요청 오류 1건이 남았다. 최종 E2E는 세 엔진 모두 오류 0을 확인한다. 두 결정은 2026-10-27 소유자 결정이다.

## M에서 찾아 고친 것

1. run이 읽은 데이터셋이 닫힘에 없어, 그 이름을 담은 그림 caption이 멈췄다(`572e5f4`, 5.3의 "run이 인용한 데이터셋의 이름").
2. 이전 CONTEXT 버전이 기준 버전과 같은 줄을 담아 문장 토큰으로 멈췄다(`572e5f4`). 리뷰 뒤 포함한 글의 한 줄과 **통째로** 같은 줄만 빼도록
   좁혔다(`ad509b2`). 처음 구현은 이어 붙인 글의 부분 문자열이면 빼서, 제외한 발견을 인용한 줄이 통과했다.
3. **누출 검사 시간**(`a543df2`): 글마다 금지 토큰 9,352개를 다시 정규화해 대조했다. `572e5f4`에서 read의 모델 단계가 290초 동안 글 31,966개를
   검사하고도 끝나지 않았고, evidence는 첫 코드 파일에서 115.5초 만에 멈췄다. 정책마다 한 번 색인한 뒤 미리보기 전체가 위 표의 값이다.
   판정은 같다(무작위 대조 시험 400건).
4. **run 코드 안의 그림 이름**(`5f056f6`·`ecc61ec`): 인용한 옛 그림의 run 코드가 뒤 버전에서 지운 그림 이름을 담아 코드 파일 8개가 멈췄고, 이어서 그림을
   만들기 전에 끝난 run의 코드가 같은 이유로 멈췄다. 포함한 run의 사본 코드 안에서만 같은 스크립트의 run들이 기록한 그림 이름을 찾지 않는다(2026-10-27
   소유자 결정 두 가지). 다른 스크립트의 코드에서는 여전히 멈춘다.
5. **같은 초의 run ID**(`acae803`): 같은 스크립트를 같은 초에 두 번 실행하면 run `X`와 `X-2`가 생기고, `X-2`만 담은 사본이 그 안의 `X`에서 멈췄다.
   main `fdd4c88`에서도 재현했다. 포함한 항목의 ID 필드 안에만 나오는 토큰은 그 ID로 본다. 따로 나온 `X`와 `<run_id>/<그림>` 키 안의 `X`는 멈춘다
   (2026-10-27 소유자 결정. 키는 리뷰 뒤 뺐다).

## 리뷰 뒤 수정

frozen `00aece7`의 독립 1·Codex 1 리뷰(재리뷰 없음)로 `d693ba6`·`ad509b2`가 고쳤다. 처분 전체는 PR 본문에 있다.

- 그림 이름 예외가 같은 값의 모든 토큰을 건너뛰어, 그림 이름과 같은 비공개 `session` 값이 통과했다 → 그림의 `visualization_id` 토큰만 건너뛴다.
- 복사되지 않는 코드 스냅샷의 현재 해시에도 이름을 등록했다 → 기록과 같아 복사되는 바이트만.
- 두 예외 모두 환경 필드에 적용되지 않는다. 문장 예외·ID 예외는 위 2·5와 같이 좁혔다.
- `plotly.min.js`가 빠진 사본의 안내가 `pages/figures/plotly.min.js`를 적었다 → `assets/plotly.min.js`. 브라우저 시험에 그 사본을 더했다.
- 엔진을 지정했는데 Playwright가 없으면 시험이 skip으로 통과했다 → 실패.

남은 멈춤 하나는 설계대로다. 그림의 첨부 표 값 `sensor_05`가 사본 밖 데이터셋 이름(8자 이상, 강한 토큰)과 같았다. 측정 도구가 사람처럼 그 그림을
제외했다. 이름 대조의 오탐이며 한계로 둔다.

## 미실행·한계

- M은 이 macOS 한 대에서 한 번씩 쟀다. Linux·Windows, 반복 측정의 p50/p95, warm·cold 구분, L 규모는 not_run이다.
- OS 보관 도구(Windows 탐색기, macOS 보관 유틸리티)로 연 확인, Safari·모바일, 실제 다른 독자는 not_run이며 소유자·#24의 몫이다.
- Firefox·WebKit은 로컬 판정이고 CI 판정이 아니다. `<meta charset>`이 없는 사용자 HTML은 엔진이 다른 인코딩으로 읽을 수 있다.
- 12.6 가운데 E2E가 열지 않은 것: `index.html`만 옮긴 사본, HTML 그림·Report frame 문서를 지운 사본, frame 안 스크립트가 `parent`에 닿지
  못함(속성만 확인하며 frame은 스크립트를 실행하지 않음), 뒤 버전으로 가는 이동이 없음. 모두 not_run이다.
- 0.27.0 이하의 `--verify`는 0.28.0 사본을 거절한다(D5의 한계).
- 이 기록은 Q14의 #20 몫이다. P1 게시(#21)와 다른 기기의 열람(#24) 없이 Q14를 통과로 적지 않는다.
