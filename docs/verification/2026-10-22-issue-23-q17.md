## Q17-a

**환경과 차단.** `tools/human_e2e.py prepare`가 clean 체크아웃의 wheel을 새 HOME에 설치했다(`uv tool install`, uv 관리 CPython 3.12.13,
분석 라이브러리 duckdb 1.5.6·polars 1.44.2·pyarrow 26.0.0·matplotlib 3.11.2·plotly 6.9.0·Pillow 13.0.0). 세션은 `sandbox-exec` 아래의
`env -i` zsh이고 다음을 모두 태그와 함께 막는다.

- 모든 외부 IP 연결(loopback 포함: 로컬 모델 서버도 모델이다)
- Unix 소켓 연결(이름 조회 포함)
- PATH에서 찾은 모델 실행기 7종(aelix·codex·claude·ollama·gemini·opencode·qwen)의 실행 경로 15곳
- 그 설정·로그인·모델 저장소 10곳(`~/.aelix`·`~/.codex`·`~/.ollama`·`~/.cache/huggingface` 등)의 읽기

`UV_OFFLINE=1`로 설치 뒤의 네트워크도 쓰지 않는다.

**계측.**
- 세션마다 시작 전에 대조군 거절 하나를 일부러 만들어 unified log에 남는지 확인했다. 남지 않으면 0을 측정하지 못한 것으로 실패시킨다.
- 셸이 끝나면 셸이 띄운 프로세스가 끝나기를 기다렸다가, 남은 것은 멈추고 그 시간의 거절을 읽는다.
  - 이 "남은 프로세스" 규칙은 측정 도중에 바뀌었다(세션별 코드는 JSON의 `measured_with`).
  - 세션 1(소유자)까지는 "OUT 아래에서 일하는 프로세스"였다. 그래서 OUT/agents에서 돌던 에이전트의 로컬 Qwen 세션을 멈췄다(결함, 고침).
  - 0회 판정은 이 규칙과 관계없이 `check`가 prepare부터 다시 읽은 로그에 기댄다.
- `check`는 prepare부터 판정 시점까지 태그 거절을 다시 읽는다.
- 그 밖에 확인하는 것:
  - 두 환경에서 aelix가 import되지 않음
  - 자격 증명 변수가 없음
  - HOME의 `.aelix`에는 kit 신뢰 목록뿐
  - 설치된 kit의 네트워크 사용은 `socket.gethostname`뿐
  - 에이전트가 아닌 기록·run이 모두 측정한 세션 시간 안에 쓰였음

**결과.**
- 에이전트가 안내서 1–5단계를 sandbox 세션 6개로 실행했다(리허설 환경 `rehearsal-3`).
- 세션마다 대조군이 1회 잡혔고 막힌 시도는 0이었다. 다시 읽은 로그도 0이고, 세션 시간 밖의 기록은 0이었다.
- 모델 호출은 0이다. 연결과 목록의 실행기가 모두 막혀 있었기 때문이다.
- 함께 확인한 것:
  - 일부러 틀린 첫 run은 `error`(ColumnNotFoundError)로 남고, 고친 run은 따로 `ok`였다.
  - SDK 경로와 일반 polars·`plt.show()` 경로 모두 코드 스냅샷·관측 입력·환경·Visualization이 기록됐다.
  - 발견을 정정(`supersedes`)하자 정정된 발견은 핵심 정보에서 빠졌다.
  - Report v1·v2를 저장한 뒤 v1 본문을 그대로 읽었다.
  - v1의 첨부(png)와 본문의 바이트는 manifest와 맞고, 근거 run 2개도 그대로다(2026-10-22, `--verify-files`).
  - 새 프로세스의 `status`·`context`에서 목적·발견·열린 항목을 회수했다.
- 소유자 환경(`~/aelix-q17`, main `b4e5b4e`에서 prepare)의 세션 5개(소유자의 Q17-a 일부와 Q17-b 검토)도 막힌 시도 0이다.
  - `check --project`는 소유자의 `q3-sales`만 덮는다.
  - 사본에 남긴 소유자 기록 e30·e31은 따로 대조했다. 각각 세션 2·3의 시간 안에 쓰였다.
- **측정하지 않은 것**: 5단계의 Workspace 이동(결과 → 데이터·코드 → 발견·보고서).
  - 에이전트는 렌더만 했다.
  - 소유자가 Q17-b 검토 세션 4·5에서 `analytics open`으로 열어 보았지만 점검표는 없었다.

**측정 범위.**
- 막지 못하는 경로가 있다.
  - 분석 코드가 다른 곳의 모델 파일을 직접 여는 경우
  - prepare 때 PATH에 없던 실행기
  - 실행기 목록은 경로로만 막아서 복사본은 실행된다. 그 원격 호출은 IP·Unix 소켓 거절이 막는다.
- 셸 밖에서 도는 편집기·브라우저는 측정하지 않는다. 안내서는 모델 기능을 끈 편집기를 요구한다.

**리허설에서 찾은 마찰**(에이전트가 겪은 것이라 사람의 사용성 결과가 아니다).
- `reports save --based-on`은 이름이 아니라 완전한 typed reference JSON만 받는다. 근거는 버전마다 따로라 v2에도 다시 줘야 한다. `record --ref`는 이름을 결박한다.
- `status`·`context`에 Report가 나오지 않는다.
- `plt.show()` 그림의 Visualization 이름은 `chart-1`이다.
- `analytics init`은 aelix가 없는 환경에서도 `~/.aelix/agent/analytics-projects.json`(kit 신뢰 목록)을 만든다.

## Q17-b

**기준 프로젝트.** `rehearsal-3`의 Q17-a 프로젝트다. 기록 23개, run 4개(실패 1), Report 2버전이고, 열린 항목은 환불 질문 e23과 결제 오류 할 일 e10이다.
에이전트 리허설이 CLI로 쓴 기록은 작성 주체를 밝히지 않아 제품 규칙대로 `human/inferred`로 남았다. 마지막에 더한 e23만 `agent/declared`다.
모델마다 저장소 밖(`~/aelix-q17/agents/<model>/project`)에 사본을 두었다. 별도 aelix 0.1.0b2 환경(같은 wheel, 새 agent 디렉터리·HOME·uv 캐시)에서
같은 요청 글([`q17b-request.md`](../../tools/human_e2e_data/q17b-request.md))로 새 세션을 열었다. 이전 대화는 넣지 않았다.

**작성 주체.** Q17-b의 aelix 세션과 소유자 검토에서는 구간마다 작성 주체가 섞이지 않았다. aelix 에이전트가 쓴 것을 사람 작성으로 기록한 경우는 없었다.
기준 프로젝트의 e1–e22는 예외다. 에이전트 리허설이 셸의 CLI로 썼지만 작성 주체를 밝히지 않아서, 제품 규칙대로 `human/inferred`로 남았다(위 "기준 프로젝트").

| 쓴 것 | 기록된 작성 주체 |
|---|---|
| aelix 도구로 쓴 기록과 run | `agent/declared/tool` |
| run 안의 SDK 기록 | `agent/declared/sdk` |
| aelix hook의 CONTEXT 동기화 | `system/declared/hook` |
| 소유자의 검토 기록 | `human/inferred/cli` |

**보존.** 매 대조에서 다음이 모두 그대로였다.
- 인계 전의 불변 파일(`analytics.json`·run·Report·가져오기·CONTEXT 버전)
- journal·query 로그의 앞줄
- run 기록과 Report 버전

gpt-6.1-sol이 고친 CONTEXT.md는 편집 가능 파일이고, 이전 버전은 `.analytics/context/`에 남았다.

**관찰.**
- Qwen의 메모 e30은 러시아어로 쓰였다. 소유자가 검토 기록에 재정리가 필요하다고 남겼다.
- **수치 확인**(합성 데이터를 다시 계산, 1–15일 기준):
  - gpt-6.1-sol의 e27(대구 앱 환불 19 → 69, +263.2%)은 맞다.
  - Qwen의 e29(대구 앱 3.18% → 8.82%, 대구 웹 2.23% → 4.44%)와 e30(부산 웹 3.33% → 2.93%)도 맞다.
  - Qwen의 SDK 기록 e28은 틀리다. 월 전체 비율(대구 앱 2.84% → 7.99%)을 "1~15일 기준"이라고 적었고, "그 외는 ±10% 내외"도 사실과 다르다(광주 웹 −32%).
  - e29는 e28을 정정(`supersedes`)으로 잇지 않았다. 그래서 서로 다른 두 발견이 모두 현재로 남아 있고, 소유자 검토(e31)도 e28을 다루지 않았다.
  - 이것은 모델 답의 품질 관찰이다. 인계 보존·작성 주체 판정과는 별개다.
- 두 모델 모두 결제 오류 할 일 e10은 데이터가 없다며 열어 두었다.

## 한계

- Q17-a의 사람 사용성은 측정하지 않았다(소유자 결정). Q17-a 기능의 판정은 에이전트 실행에 의한 것이다.
- Q17-b 세션은 소유자의 요청으로 에이전트가 터미널 없이 띄웠다(`--mode json -p`, 프로젝트는 `AELIX_ANALYTICS_PROJECT`).
  사람이 aelix 화면에서 요청을 붙여 넣는 경로는 이번에 수행하지 않았다.
- Q17-b 세션은 sandbox 밖에서 돈다(모델 호출이 목적). 모델 사용량은 Q17-b에만 셌고, Q17-a의 0회와 섞지 않았다.
- Q17-b의 사람 구간은 판단 기록(`decision`) 하나씩이다. 정정이나 Report 새 버전은 남기지 않았다.
- Q17-b 환경은 이 PR 전의 `agent-env`로 만들었다. `start-print.sh`는 같은 내용을 손으로 만든 사본이다. 지금의 `agent-env`는 이를 직접 쓰고, 지침 파일·git 아래를 거절한다.
- OpenRouter의 Qwen은 지원 하단의 로컬 기준 서빙(`qwen3.8-27b-local`, Q4_K_M, ollama 0.35.1)과 같은 서빙이 아니다.
- §3 캠페인(Q2·Q13 등의 실제 모델 과제)과는 묶지 않았다. 프론티어 모델의 선택은 #24에서 정한다.
