## 읽기(`reader`)

기록 예제 여섯(`tests/fixtures/records`)을 기준과 헤드의 읽기 모델로 읽었습니다. 참조 판정·확정 연결 수·`unsupported`·끊긴 줄·복구한 줄·기록
상태·run과 가져오기의 기록 상태는 여섯 모두 같고, 다른 것은 목록에 보이는 기록 수뿐입니다(헤드는 `analytics.event/2` 기록도 보임).

| 예제 | 참조 판정(앞=뒤) | `unsupported`(앞=뒤) | 목록의 기록 수 앞 → 뒤(그 가운데 `/2`) |
|---|---|---|---|
| `normal` | resolved 20, unknown 1, version_unbound 1 | 0 | 0 → 15(15) |
| `mixed-version` | ambiguous 2, missing 1, resolved 10, unknown 1, version_unbound 4 | 0 | 8 → 10(2) |
| `interrupted` | resolved 3 | 0 | 0 → 5(5) |
| `conflict` | resolved 7 | 0 | 0 → 8(8) |
| `missing` | content_changed 1, missing 7, resolved 1, unknown 1 | 0 | 0 → 4(4) |
| `future-version` | resolved 1, unsupported 3 | 4 | 0 → 4(4) |

새 가족 예제(같은 스크립트의 `lab.run/1` run과 `analytics.run/2` run, `data/imported/`의 `analytics.dataset/1` 기록): 기준은 `/2` run을
`unsupported`(`unknown_version`)로 세고 Visualization 키의 버전이 1개, 데이터셋 0개입니다.
헤드는 `/2` run을 읽어 버전이 2개(`/1`·`/2`가 같은 키), 가져오기 기록과 데이터셋(`imported`)을 읽습니다.

## 쓰기에 더해진 시간(`gate_cost`)

1,000줄 journal의 lab.json 프로젝트에 `core.add_note` 200번, 노트당 평균. 기준과 헤드를 번갈아 두 번 재고 각각의 최솟값입니다.

| 측정 | 기준 `5829c7c` | 헤드 `634479b` |
|---|---|---|
| 노트 한 번(ms, 최솟값) | 1.8828 | 1.9408 |
| 차이 | | +0.058 ms(+3.1%) |
| `writer.marker_state` / `core.admit` 한 번(µs, 헤드) | | 18.94·19.32 / 20.7·20.83 |

journal 쓰기는 판정을 두 번 합니다(잠금 전과 잠금 안). 한 번은 표식 두 개의 `stat`과 작은 JSON 하나의 읽기라 이 기기에서 약 20 µs이고, 차이는
네 번의 측정 사이의 흔들림(1.88–2.02 ms) 안입니다. FIFO 가드 전의 헤드 `cdba47a`에서 잰 값은 1.9182 → 1.9635 ms였습니다.
