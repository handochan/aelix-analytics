Qwen R2의 두 실패는 성격이 다르다.
- **T04의 한계**: A의 한 run이 잘린 기록의 길이를 4,000자가 아니라 바이트로 말했다(Part I).

  나머지 하나(A)는 맞는 ID와 나란히 잘못 쓴 ID다(`20261104-003146-00:31-01-…`).
  채점기는 "…"로 줄인 ID만 줄임으로 본다. 그래서 넷 모두 없는 ID로 셌다.

R4의 "해당 없음"은 앞 세션이 그 값을 내지 못한 회수 검사다. 주로 C1(EDA가 C057·C035 말고 다른 후보를 듦)과 C2의 세션 1(처음부터 같은 일수로 비교해 22.0%를 내지 않음)이다.
뺀 짝은 gpt 11/30, Qwen 12/30으로 절반을 넘지 않아 R4를 판정했다.

## 소유자의 판정(2026-11-04)

이 기록을 본 뒤 소유자가 출시를 앞당기며 다음을 정했다([설계 13절](../design/PRODUCT-EVALUATION.md#13-정한-것2026-10-31-소유자)의 O9–O11, #24).
위의 값과 규칙의 판정은 바꾸지 않는다.

- **Qwen3.8 27B: R2를 알려진 원인으로 수용하고 0.32.0으로 출시한다(O11).** T04의 한계는 기록 읽기가 글자 수를 주지 않아서이고
  ([#156](https://github.com/handochan/aelix-analytics/issues/156)), 없는 ID는 대부분 run ID를 날짜·시각·순번까지만 줄여 쓴 것이다

## 무엇을 돌렸나

- **조건**: A는 aelix + aelix-analytics(기본 표면, 제안 없음), V는 aelix만이다. 두 조건이 같은 요청 글과 같은 fixture를 받는다.
- **과제**:
  - Part I: 14과제(T01–T14) × 3회 × 2조건 = 모델마다 84 run
  - Part II: 체인 3개(C1–C3) × 세션 3 × 3회 × 2조건 = 모델마다 54 세션
  - 체인의 요청 글은 두 조건 모두에 여러 세션에 걸쳐 이어 간다고 알린다(O1). 세션 사이에 작업 폴더는 같은 경로로 이어지고 대화는 이어지지 않는다.
- **순서**: A와 V를 과제마다 번갈아 돌리고, 먼저 도는 쪽을 반복마다 바꿨다(O8). 두 차례로 나눠 돌았다. 1부(T01–T12)는 2026-11-01 12:31–13:47 KST, 2부(T13·T14·체인)는 2026-11-04 00:10–01:40 KST다. 두 모델은 병렬로 돌았다.
- **kit**: 0.32.0, 확장 sha256 `78f90116…`. 출시 후보(`26c28d0`)와 `src/`·`extension/`이 같다. 하네스 checkout은 `77a170d`(clean)다.
  비교 도구가 kit 커밋이 다른 run을 따로 떼어 내므로, 2부도 1부와 같은 checkout에서 돌렸다. aelix 0.1.0b2, Python 3.12.13, macOS 26.6.2 arm64다.
- **모델**: gpt-6.1-sol(aelix 로그인), `qwen/qwen3.8-27b`(OpenRouter, 업스트림 공급자는 요청마다 OpenRouter가 고름).
- **결과**: 276 run 모두 실행됐다. `error`·`not_run`은 0이다.
