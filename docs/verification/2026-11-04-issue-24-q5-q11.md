# Issue #24 — 재사용 제안(Q5)과 도구 표면(Q11) (2026-11-04)

[Issue #24](https://github.com/handochan/aelix-analytics/issues/24) 출시 리허설에서 Q5와 Q11을 잰 기록이다. 소유자가 첫 베타 전에 재기로
정했다(2026-11-04). 수치의 정본은 [JSON](2026-11-04-issue-24-q5-q11.json)이다. 원자료(run 50개)는 이 기기의 run 디렉터리에 두고 커밋하지 않았다.

- **이 기록이 잰 Q5의 기준**(BETA §2·§3 "제안 옵션과 도구 표면의 별도 측정"의 일부. 나머지는 [측정하지 않은 것](#측정하지-않은-것)):
  - 요청하지 않으면 제안을 꺼내지 않고 제안 턴도 없다.
  - 요청하면 답하고, 그 턴의 토큰을 따로 센다.
  - 상시 조건에서 제안을 위해 모델을 부르지 않는다. 판정·알림의 동작은 결정적 시험으로 본다.
  - 요청·상시 조건에서 필수 사실의 완수가 무요청보다 줄지 않는다.
  - 정책(문턱·중복·cooldown·취소 등)의 결정적 시험이 통과한다.
- **Q5의 결과**: 위 기준을 모두 만족했다.
  - 요청하지 않은 run(E4의 A)과 상시 조건 run에서 제안을 꺼낸 답은 0개다.
  - 요청한 run은 모두 제안 요청에 답했다(gpt 9/9, Qwen 6/6). 이 검사는 답했는지만 보는 낱말 검사라("없습니다"만으로도 통과) 제안의 유효성은 판단하지 않는다.
  - 상시 조건은 모든 run에서 모드가 설정됐다. 어느 run에서도 제안 후보 기록(`asset_candidate`)이 생기지 않아 알림(`asset_notification`)은 0건이고,
    제안을 위한 모델 호출도 없었다. 후보가 없는 세션의 0건은 [제안 정책](../SKILL-PROPOSAL-POLICY.md)대로 정상이지만, 문턱 판정과 알림의 경로는 실제 세션에서 실행되지 않았다.
  - 결정적 시험은 후보 CI([41150692492](https://github.com/handochan/aelix-analytics/actions/runs/41150692492), `26c28d0`)에서 세 OS 모두 178개가 통과했다.
- **Q11의 기준**: 이 판은 새 도구를 더하지 않았다. 호스트의 전체 목록(`default`, 14개: aelix의 8개와 확장의 6개)에서 확장의 도구를 쓰는 것이
  좁은 표면(`coding` 10개, `analytics_read` 7개)보다 인자 오류와 완수에서 나쁘지 않아야 한다.
- **Q11의 결과**: 에이전트의 판단으로 기준을 만족했다. 좁은 표면이 마친 과제는 전체 목록에서도 마쳤다(Qwen T11은 3회 중 2회).
  - 하네스가 인자 오류로 분류한 것(알 수 없는 도구, schema 위반, `run_args` 같은 도구 인자 거절)은 전체 목록에서 두 모델 모두 0이다.

## Q5: 제안 조건

필수 사실은 통과 수/검사 수다. "제안"은 덧붙인 제안 요청에 답한 run 수, "제안 턴"은 그 요청에 답하느라 쓴 토큰의 중앙값이다. 토큰은 run 전체
(비캐시·캐시 입력과 출력)의 중앙값이다. 무요청은 E4의 A run(반복 3회)이다.

| 모델 | 과제 | 무요청: 성공 · 사실 · 토큰 | 요청: 성공 · 사실 · 토큰 · 제안 · 제안 턴 | 상시: 성공 · 사실 · 토큰 · 알림 |
|---|---|---|---|---|
| gpt-6.1-sol | T07 | 2/3 · 5/6 · 83k | 3/3 · 6/6 · 84k · 3/3 · 12k | 2/3 · 5/6 · 83k · 0 |
| gpt-6.1-sol | T08 | 0/3 · 7/9 · 78k | 0/3 · 9/9 · 126k · 3/3 · 14k | 0/3 · 9/9 · 71k · 0 |
| gpt-6.1-sol | T12 | 0/3 · 6/9 · 454k | 2/3 · 9/9 · 644k · 3/3 · 167k | 0/3 · 6/9 · 493k · 0 |
| Qwen3.8 27B | T07 | 2/3 · 6/6 · 159k | 3/3 · 6/6 · 168k · 3/3 · 53k | 2/3 · 6/6 · 119k · 0 |
| Qwen3.8 27B | T08 | 1/3 · 9/9 · 136k | 0/3 · 9/9 · 132k · 3/3 · 37k | 2/3 · 9/9 · 114k · 0 |
| Qwen3.8 27B | T12 | 0/3 · 8/9 · 3,129k | 미실행(402) | 0/1 · 3/3 · 1,455k · 0 |

- **성공**은 자동 채점이다. 무요청(E4)에서 소유자가 오판으로 확정한 검사를 빼면 Qwen T07·T08의 무요청 성공은 둘 다 3/3이다. 새로 돈 run에서 중대 오판 검사가 6건 걸렸고, 사람이 확정하지 않았다(아래). 그래서 Q5의 판정에는 성공 대신
  필수 사실을 썼다. 걸린 검사는 E4에서 모두 오판으로 확정된 것과 같은 종류다(T07 `wrong-rate`, T08 `decline-as-current`).
- **gpt T12의 제안 턴(167k)**: 제안 요청에 답하는 턴에서 모델 요청이 4–5번이었다(상태 조회·파일 읽기, 두 run은 기록도 남김). 요청마다 T12의
  긴 대화가 입력에 다시 들어가 토큰이 커졌다. 요청한 사람이 그 비용을 고른 것이고, 무요청·상시 조건에는 그 턴이 없다.

## Q11: 도구 표면

`default`는 E4의 A run(반복 3회), `coding`·`analytics_read`는 반복 1회다. 원시 읽기는 kit의 기록 파일(journal, run 기록)을 기본 도구로 직접
읽은 호출이다.

호출은 중앙값, 오류·인자 오류·원시 읽기는 합이다. 호출과 오류는 표면마다 run 수가 달라(3과 1) 합을 그대로 견주지 않는다.
인자 오류는 하네스의 분류(알 수 없는 도구·schema 위반·도구 인자 거절)이고, kit의 `bad_query`는 오류에만 든다(위 Q11의 결과).
bash가 없는 `analytics_read`에서 Qwen은 T05에서 인자 오류 4건(`run_args`)을 냈다.

## 무엇을 돌렸나

- **checkout**: E4와 같은 `77a170d`(clean)다. 그래서 E4의 기본 표면·무요청 A run이 기준선이 된다. `src/`·`extension/`은 출시 후보 `26c28d0`과 같다.
- **과제**:
  - Q5: T07·T08·T12를 기본 표면에서 제안 요청(`requested`)과 상시(`always_on`)로 3회 돌렸다. 두 조건은 반복마다 순서를 바꿨다.
  - Q11: T03·T05·T06·T11을 `coding`과 `analytics_read`로 1회 돌렸다(시범 캠페인과 같은 구성).
- **시간**: 2026-11-04 10:54–11:40 KST. 두 모델은 병렬로 돌았다.
- **OpenRouter의 402**:
  - Qwen은 크레딧이 떨어져 run 3개가 끝나지 못했다. T12 requested r1과 T07 always_on r2는 실행 도중에 `error`, T07 requested r2는 시작 전에 `not_run`이 됐다.
  - 소유자가 충전한 뒤 Qwen의 남은 run을 다른 출력에 다시 돌렸다(16 run). 같은 run은 실행된 쪽을 쓴다.
  - T12는 비용이 커서 소유자가 Qwen은 반복 1까지만 두기로 했다. T12 requested r1은 402로 끝나 Qwen의 T12 requested는 없다.
- **결과**: gpt 26 run(성공 15, 실패 11), Qwen 21 run이 실행됐다(첫 출력 5, 다시 돈 16).
  - 비밀 검사는 실행된 47 run 모두 통과했다.
  - 402로 끝난 Qwen run 3개는 OpenRouter 오류 본문의 계정 정보가 자격 증명 모양으로 걸려 가려졌다(시범 캠페인과 같음). 그 가운데 T12 requested r1은
    kit의 참조 필드(`"token": …`)도 자격 증명 필드로 걸려 그 run의 프로젝트 journal이 가려졌다. 비밀 검사의 오탐이고, 판정에 쓰지 않는 run이다.
  - 로그인의 값과 바이트 단위로 같은 글은 50 run 모두에서 0건이다.
- **채점**: main `53cc9f0`(채점기는 `5db7477`과 같음, E4와 같은 기준)으로 모든 run을 다시 채점했다. 실행 때의 채점과 바뀐 검사는 없다.

## 측정하지 않은 것

- 실제 세션에서 상시 조건의 문턱 판정과 알림(이 run들에서는 제안 후보 기록이 생기지 않았다). 알림의 발행·창·취소는 결정적 시험으로만 확인했다.
- 제안의 유효성·중복(BETA §3), 알림 뒤 사람이 요청하지 않은 상세 검토 0회와 표면별 유효 제안률(ADR-0008 결정 9), 등록·보류 예제 각 1개
  (BETA §2의 Q5 행). 이 기록의 제안 요청 검사는 답했는지만 본다.
- Qwen T12 requested(402)와 Qwen T12의 반복 2–3(소유자 결정).
- 좁은 표면의 반복 2회 이상, 도구 schema·시스템 프롬프트의 바이트(aelix 0.1.0b2가 요청 본문을 내지 않음).
- 로컬 Qwen([설계](../design/PRODUCT-EVALUATION.md) O10).
