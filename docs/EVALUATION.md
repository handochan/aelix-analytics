# aelix-analytics 평가 가이드 — baseline 대비

작성 2026-09-16. 비교 대상은 aelix-analytics **계약 0.2**([계약](../../aelix-analytics/docs/contracts/02-core-contracts.md),
[ADR-0001](../../aelix-analytics/docs/decisions/0001-verified-analysis-contracts.md))입니다. 그쪽은 slice 3(계약 0.3)이
진행 중이므로 평가할 때 버전을 함께 적으세요.

## 1. 왜 baseline인가

두 확장은 목표가 같습니다 — HTML로 분석하고, 모든 차트에서 데이터와 코드를 확인하고, 맥락과 이력을 남긴다.
방법이 다릅니다.

- **aelix-analytics**: 검증 가능한 기록을 **계약으로 강제**합니다. hash-chained 원장, 불변 번들, 선언형 ViewSpec,
  스냅샷에 결박된 SelectionRef, 캐시 없는 재실행 verify, keyed 멱등 작업과 recover, 격리된 DuckDB SQL transform.
- **baseline**: 자유로운 Python 코드에 **가벼운 규약**(run 기록, journal, CONTEXT.md)만 얹습니다.

같은 과제를 둘 다로 해 보면 각 계약이 **실제로 막아 주는 실패**와 **치르게 하는 비용**이 드러납니다.
결론의 형태는 셋 중 하나입니다: 이 계약은 필요하다 / 가벼운 규약으로 충분하다 / 계약이 과하니 완화한다.

## 2. 비교 축

| # | 축 | baseline | aelix-analytics 0.2 | 관찰할 것 |
|---|---|---|---|---|
| 1 | 분석 표현력 | 임의 Python: DuckDB·Polars·matplotlib·plotly·통계 라이브러리 | ViewSpec v2(scatter/line/bar, count/sum/mean, 색 8범주) + DuckDB SQL transform(SELECT 한 문장, 입력 8개, 결과 1–2,000행). Python·Polars transform 없음 | 과제를 끝냈나, 어디서 막혔나(gap 수) |
| 2 | 차트 → 코드 | run 코드 스냅샷(실행된 바이트), 차트 기록 줄 강조 | 뷰 번들의 실제 실행 코드 + 생성된 reproduce.py (binding exact/generated) | 사람이 코드를 읽고 수치를 이해하는 데 걸린 시간 |
| 3 | 차트 → 데이터 | 입력 sha256(감지는 최선 노력) + `lab.chart(data=)` 플롯 데이터 | 선언 입력만 읽는 격리 + plotted·row_map Parquet, 집계 → 원본 행 연결 | 감지 누락이 있었나, 원본 행까지 내려갈 필요가 있었나 |
| 4 | 무결성 | sha256 기록, 해시 체인·잠금 없음, 직접 수정 허용 | hash-chained 원장, 불변 번들 파일 규칙(fail closed) | 사고로 기록이 틀어진 적이 있었나, 그걸 누가 먼저 알아챘나 |
| 5 | 재현 | `rerun_of`: 스냅샷 재실행, 플롯 데이터 동등성·출력 바이트, 환경 비교 없음 | `verify`: 캐시 없는 재실행, 환경 불일치 시 `environment_unavailable`, row/value hash | 재실행이 필요했던 순간, 판정을 믿을 수 있었나 |
| 6 | 선택·후속 분석 | 없음 — 조건을 코드로 옮김 | SelectionRef: 사람 마킹 ↔ 에이전트 조건이 같은 원본 행 집합 | "이 점들만" 같은 의도를 전달하는 비용 |
| 7 | 실패·중단 | run `status`(error·timeout·cancelled·incomplete), 트랜잭션 없음 | keyed 작업 템플릿, Store.commit, recover(quarantine) | 중단 뒤 상태가 일관적이었나, 사람이 수습해야 했나 |
| 8 | 재시도·중복 | 멱등 키 없음(재시도 = 새 run) | `--key` 멱등 | 중복 run이 혼란을 만들었나 |
| 9 | 맥락·결론 | CONTEXT.md 버전 + journal(finding·decision·question…) + 매 요청 프롬프트 주입 | 0.2 비목표: note·finding·승인, 턴마다 digest 주입 | 새 세션에서 모델이 맥락을 정확히 복원했나 |
| 10 | 에이전트 인지 비용 | 도구 6개, 텍스트 결과 + 차트 이미지 | 도구 8개, digest 예산·`show part` | 도구 호출 수·오류 수·토큰(텔레메트리) |
| 11 | 사람 인터페이스 | 정적 HTML(탭·버전·stale·계보·diff, 자동 새로고침) | 연결 모드 뷰어(축·색 변경, 마킹, 선택 저장, 후속 분석) + 합성 데이터 정적 export | 사람이 직접 해 보고 싶었던 조작 |
| 12 | 안전·반출 | 샌드박스·승인·가림 없음 | 격리(샌드박스 아님), 가림 규칙, 실데이터 정적 반출 금지 | 공유하려 할 때 막힌 점, 위험했던 순간 |
| 13 | 규모 | 상한 없음, 리포트 전체 재생성 | 명시 상한(파일 256 MB·100만 행 등), 원장 전체 읽기 | 데이터가 커질 때 먼저 무너지는 곳 |

## 3. 시나리오

**같은 데이터와 같은 질문으로 두 확장을 각각** 새 aelix 세션에서 진행합니다. 모델·thinking 수준을 같게 두세요.
`bin/lab demo`의 합성 데이터나 실제로 답해야 하는 작은 질문을 씁니다.

| # | 시나리오 | 요청 예 | 관찰 |
|---|---|---|---|
| S1 | 시작 | "이 CSV로 분석 프로젝트를 시작하고 데이터 구조를 설명해줘" | 호출 수, 오류, 모델이 스키마·기간·결측을 맞게 말했나 |
| S2 | 첫 차트 | "월별·채널별 매출 추세 차트" | 차트 하나의 수치를 사람이 원본까지 확인하는 데 걸린 분 |
| S3 | 표현력 한계 | 이동평균·신뢰구간, 두 데이터셋 조인 후 파생 지표, 산점도+회귀선, 박스플롯 | 끝냈나, 우회했나, 무엇이 막았나 |
| S4 | 반복 수정 | 같은 차트를 필터·집계 기준을 바꿔 세 번 고치기 | 버전 이력이 이해되나, 이전과 비교되나 |
| S5 | 선택 기반 후속 | "튀는 점들만 따로 원인을 보자" | 사람의 의도(마킹)를 전달하는 방법과 정확도 |
| S6 | 데이터 변경 | 수정된 v2 파일을 새로 들여오기 | 영향받는 차트·결론이 드러나나(stale, 원장) |
| S7 | 재현 | 다음 날 새 세션에서 차트 하나 재현·검증 | rerun `match` vs verify `match`, 환경이 바뀌면 |
| S8 | 중단·실패 | 긴 실행 중 중단, 스크립트 오류, 같은 요청 재시도 | 기록 일관성, 수습 절차 필요 여부 |
| S9 | 이어받기 | 세션을 닫고 "어디까지 했지? 남은 질문은?" | 맥락 복원 정확도, 틀린 기억 |
| S10 | 공유 | 결과를 동료에게 넘길 HTML | HTML만으로 설명되나, 실데이터 노출 위험 |
| S11 | 규약 위반 | 모델이 bash로 python을 돌리거나 `data/raw`를 고치는 상황 | 텔레메트리 플래그, 기록 누락이 리포트에서 드러나나 |

## 4. 기록하기

baseline 쪽:

- 불편·누락은 그 자리에서 `/lab gap <무엇을 하려다 무엇이 안 됐나>`. 리포트 **평가** 탭에 모입니다.
- 도구 사용은 `.lab/telemetry.jsonl` → 평가 탭의 도구별 호출·오류·평균 시간, 우회 의심 호출.

## 5. 결론을 내리는 기준

- baseline에서 **틀린 결론이나 검증 실패가 실제로 났고** aelix-analytics의 계약이 그것을 막았다 → 그 계약은 필요합니다.
- baseline의 gap이 반복되지만 **가벼운 규약 추가**로 풀린다 → 경량 대안을 먼저 검토합니다.
- aelix-analytics의 **제약 때문에 과제를 끝내지 못했다** → 계약 완화 후보입니다.
- 공통 지표: 차트 1개의 수치를 원본까지 확인하는 **사람 검증 시간**, 시나리오당 **도구 호출·오류 수**, **gap 수**.
