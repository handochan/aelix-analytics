## 1. 보고서는 분석 과정의 독립 산출물이다

**분석 중 언제든 내용을 보고서로 정리하고, 당시 내용·근거·버전을 보존한다.**
중간 경과 보고, 특정 질문의 검토 메모, 여러 컬럼에 대한 차트 묶음, 팀 회의용 요약, 최종 보고서가 같은 경로를 사용한다.
분석 완료나 지표 정의 확정을 작성 조건으로 삼지 않는다. 보고서를 작성해도 원래 분석은 계속된다.

| 개념 | 역할 | 수명 |
|---|---|---|
| Workspace — 현재 `report/`, 목표 `workspace/` | 기록 전체를 개요·시각화·데이터·이력 등으로 탐색 | 원본에서 재생성하는 분석 인터페이스 |
| 보고서 — 새 `Reports` 탭의 항목 | 선택한 내용을 특정 독자·목적으로 정리한 자유 형식 산출물 | 저장한 본문·첨부·참조를 버전별로 보존 |
| 게시본 `publication` | 선택한 분석 내용이나 보고서 버전을 독립 패키지로 공유 | 빌드와 게시 이력을 가진 고정 스냅샷 |

기존 `lab report`와 `/lab report`의 프로젝트 HTML 갱신 역할은 새 `analytics render`와 `/analytics render`로 옮긴다.
앞선 옛 명령 유지안은 이 명칭 전환으로 대체한다. Report라는 이름은 개별 문서 산출물에 사용한다.
화면을 다시 만드는 작업이 개별 보고서를 새로 작성하거나 기존 내용을 고쳐서는 안 된다.
같은 보고서 버전을 여러 게시본에 넣을 수 있고, 하나의 게시본에 여러 보고서 버전을 담을 수 있다.

## 2. 본문은 자유롭게, 관리 정보는 작게

보고서에 고정된 목차·차트 종류·템플릿·DSL을 강제하지 않는다. 사람이나 에이전트가 Markdown·HTML·그림·문서 파일을
직접 작성하거나 기존 Python 코드·라이브러리·선택한 템플릿으로 생성할 수 있다. 외부에서 만든 파일도 등록할 수 있다.
템플릿은 반복 작업을 돕는 선택 기능이며, 사용 가능한 보고서의 형식을 정하는 허용 목록이 아니다.

등록은 기존 쓰기·실행 흐름에서 제공하는 작은 SDK/CLI 경로를 우선한다. 파일을 만들었다는 이유만으로 모든 출력을 보고서로 자동 분류하지 않는다.
전용 상시 모델 도구의 신설을 기본값으로 삼지 않고, 기존 읽기·쓰기·실행 표면을 활용한다. 최종 노출 방식은 도구 선택 정확도·인자 오류·전체 과제 비용으로 검증한다.
ID·기록 시각·파일 형식·크기·해시는 시스템이 채우고, 작성자는 제목·필요한 설명·알려진 근거를 연결한다.
초점·지표가 미정이거나 근거를 연결하지 않은 보고서도 저장하되, 무엇이 미연결인지 표시한다.
모델이 복합 ID·파일 해시·버전 번호를 직접 계산하거나 매번 긴 메타데이터를 작성하게 하지 않는다.

첫 베타는 Markdown·HTML의 보기와 일반 파일의 보존·다운로드를 우선한다.
PDF·슬라이드 등도 파일로 보존할 수 있으나, 각 형식의 생성·변환·본문 검색·브라우저 미리보기 지원은 별도 능력으로 표시한다.
모든 문서 변환기를 기본 의존성으로 설치하지 않는다. 미지원 형식은 원본 다운로드와 알려진 메타데이터를 제공한다.
임의 HTML의 스크립트는 프로젝트 화면과 분리된 보기에서 다루며, 격리·자원 지원이 검증되지 않은 형식에는 정적 미리보기나 다운로드를 제공한다.
본문 형식의 자유와, 프로젝트 UI 안에서 실행할 수 있는 콘텐츠의 범위는 구별한다.

## 3. 정체성·버전·시간

보고서의 논리적 ID와 저장한 버전의 ID를 나눈다. 예를 들어 `sensor-review`의 Version 1, Version 2는 같은 보고서의 이력이며, 주소는 `revision_id`를 쓴다.
파일명이나 수정 시각만으로 버전을 식별하지 않는다. 아래 표의 정체성·작성 주체·`created_at`·`based_on`·파일 manifest의 필수 필드는
[ADR-0006](decisions/0006-common-record-contract.md) 7절로 채택했다(manifest 가족 `analytics.report_revision/1`, 개별 버전 저장은 kit 0.21.0에 구현).
`scope`·생성 경로·용도·묶음은 #19가 같은 manifest의 선택 필드로 확정한다.

| 기록 | 내용 |
|---|---|
| `report_id`, `revision_id`, `previous_revision` | 보고서와 저장 버전의 정체성, 어느 버전을 고쳤는지 |
| 제목·선택적 요약·작성 주체 | 무엇을 누구에게 정리했는지, 사람/에이전트/외부 가져오기 구분 |
| `created_at`, 등록 이벤트·순서 | 이 버전을 프로젝트에 저장한 시각과 순서. 외부 문서의 원래 작성일은 별도 출처 있는 값으로 기록 |
| `based_on` | 작성에 사용한 분석 초점·CONTEXT 버전·기록 기준(`as_of_seq`)과 정확한 근거 참조. 알 수 없는 값은 미확인 |
| `scope` | 대상 컬럼·필터·그룹·기간 등 이 보고서가 설명하는 범위 |
| 파일 manifest | 진입 파일·첨부·상대 경로·형식·해시·바이트 보존 상태와 외부 의존성 |
| 생성 경로 | 연결된 run·코드 스냅샷·입력·환경, 템플릿을 썼다면 그 버전·인자. 관측하지 못한 경로는 미확인 |
| 용도·상태 | 중간/최종 등 작성 목적, 내용 완전성, 검토·철회 이력을 각각 구분 |
| 선택적 묶음·구성원 키 | 컬럼별 보고서 묶음 또는 반복 생성의 대응 관계 |

`created_at`은 저장 시각, `based_on`은 작성 근거의 기준, `scope`의 기간은 분석 대상 기간이다.
예를 들어 9월 18일에 9월 17일까지의 분석 기록으로 8월 데이터를 설명하는 보고서를 만들고 9월 19일에 게시할 수 있다.
게시 시각·주소는 별도 게시 기록에 속한다. 원본을 뒤늦게 등록할 때 그 시점의 최신 맥락을 원래 작성 근거라고 채우지 않는다.

`based_on`의 프로젝트 기록 기준은 출처를 찾는 시작점이며, 본문 전체가 그 시점의 모든 데이터를 검토했다는 뜻이 아니다.
run·차트·지표 정의·데이터 관측의 정확한 버전을 함께 연결한다. journal 마지막 순서만으로 파일 전체의 스냅샷을 보장하지 않는다.
시각화 참조는 같은 논리적 시각화의 최신본이 아니라 `run_id + visualization_id`를 가리킨다. 기존 chart 필드와 정확한 버전의 대응을 reader에서 검증한다.

### 저장한 버전의 보존

- 편집 중인 작업 파일은 자유롭게 바꿀 수 있다. 저장한 버전은 본문·필요한 첨부를 보존 영역에 고정하고 일반 쓰기로 덮어쓰지 않는다.
- 문장 수정이나 새 데이터 반영은 새 버전을 만든다. 변경 이유와 이전 버전을 연결하며, 과거 링크는 계속 과거 내용을 가리킨다.
- 내용·근거 버전과 renderer·템플릿·파일 형식 버전을 구별한다. 화면 CSS를 바꾸거나 목록을 다시 만들었다고 새 보고서 버전이 생기지 않는다.
- 같은 내용의 PDF 등 별도 표현물을 추가할 때는 원본 보고서 버전·변환 도구·새 파일 해시를 연결한다. 원본 파일 manifest를 조용히 바꾸지 않는다.
- 검토·철회·후속 보고서 연결은 별도 이벤트다. 원래 본문을 고치거나 ‘최종’이라는 제목을 승인·정확성 인증으로 해석하지 않는다.
- 동시에 같은 이전 버전을 갱신한 경우 기대 버전을 검사하고 충돌(`revision_conflict`)을 드러낸다. 가지를 만들지 않으며, 벽시계상 마지막 작성만으로 다른 변경을 버리지 않는다.

보고서를 인용할 때는 버전 주소를 기본으로 한다. 최신 보기 주소는 이동 가능한 별도 링크이며 자동으로 인용 대상을 바꾸지 않는다.
새 데이터·정의·발견이 생기면 영향받는 보고서에 갱신 가능/근거 변경을 표시한다. 과거 보고서 본문은 자동 수정하지 않는다.
과거의 철회 상태와 현재 확인된 경고도 구분해, 당시 무엇을 보고했는지와 지금 무엇을 주의해야 하는지 함께 알 수 있게 한다.

## 4. 여러 컬럼과 반복 생성

반복의 단위와 버전의 단위를 구별한다.

| 요청 예 | 생성 방식 | 다음번 갱신 |
|---|---|---|
| 여러 센서를 한 번에 검토 | 한 보고서 안에 센서별 섹션·차트 | 같은 보고서의 다음 버전 |
| 컬럼마다 개별 차트 보고서 | 개별 보고서와 이를 묶는 컬렉션 | 구성원별 다음 버전과 새 묶음 스냅샷 |
| 매주 같은 조건으로 경과 보고 | 같은 보고서의 버전 또는 회차별 보고서 묶음 중 선택 | 선택한 단위를 유지하고 대상 기간을 명시 |

컬렉션의 각 저장본은 구성원의 정확한 `report_id + revision_id`를 고정한다. 과거 묶음의 일부만 최신 보고서로 바뀌지 않는다.
컬럼 이름·데이터셋 관측·필터·기간·지표 정의·정렬 순서·생성 인자를 기록해 어떤 범위를 요청했고 무엇을 만들었는지 확인한다.
성공·실패·미생성 항목을 함께 남긴다. 예를 들어 20개 컬럼 중 18개를 만들었다면 ‘18/20, 일부 완료’로 표시한다.
실패한 두 항목을 추가 생성할 때 성공한 18개의 분석을 자동으로 다시 돌리지 않는다. 새 묶음 버전에서 완료된 구성원을 참조할 수 있다.

정의가 다른 센서 지표를 단위 확인 없이 동일 척도로 비교하지 않는다. 생성기는 표시 범위를 남기고, 비교가 적절한지는 분석의 검사 대상으로 둔다.
템플릿·인자를 보존했다는 사실만으로 임의 Python 생성기의 동일 결과·외부 부작용 멱등성을 보장하지 않는다.
반복되는 생성 로직의 모듈화·skill 제안은 기존 [선택 정책](SKILL-PROPOSAL-POLICY.md)을 따른다. 보고서마다 자동 제안을 시작하지 않는다.

## 5. `Reports` 탭과 연결된 탐색

**목록 → 보고서 내용 → 근거·버전·생성 방법** 순서로 공개한다. Overview와 Insights 가까이에 `Reports` 탭을 둔다.
시스템 label·속성·기본 템플릿은 영어이며, 보고서 본문·시각화 제목·사용자 데이터의 언어는 보존한다.
현재 지표·질문 필터를 공유하고, 관련 지표를 아직 정하지 않은 보고서도 목록에서 찾을 수 있게 한다.

- 목록: 제목·짧은 설명·중간/최종 용도·저장 시각·분석 기준·버전·부분 완료 여부. 기본은 보고서별 최신 저장본이며 전체 이력을 펼칠 수 있다.
- 상세: 본문과 함께 이 버전의 시점·범위를 먼저 보여 준다. 목차나 컬럼 선택기로 필요한 부분에 바로 이동한다.
- 근거: 인용한 지표 정의·발견·당시 차트·데이터·실행으로 이동한다. 본문 전체를 읽어야만 근거를 찾을 수 있는 구조는 피한다.
- 이력: 이전 버전·변경 이유·본문 비교가 가능한지 표시한다. 바이너리 파일은 비교 지원 여부와 파일·근거 변경을 보여 준다.
- 공유: 선택한 보고서 버전을 미리보기·build·publish로 이어 간다. 저장만 했다는 이유로 외부에 게시하지 않는다.

차트·발견 상세에는 이를 인용한 보고서로 돌아가는 링크를 둔다. 보고서에서 근거를 보고 돌아올 때 버전·섹션·컬럼·스크롤을 유지한다.
외부 PDF처럼 내부 위치로의 이동을 지원하지 않는 형식은 연결된 근거 패널과 다운로드를 제공하고 지원 범위를 명시한다.
타임라인에는 작성·수정·철회·게시를 구별해 남긴다. 컬럼 100개 생성은 묶음 요약부터 보여 주고 개별 항목은 펼친다.

관계 그래프는 기록된 `인용`, `생성 실행`, `이전 버전`, `묶음 구성원`, `게시본에 포함` 관계를 사용한다.
보고서가 발견을 인용했다고 그 발견을 독립적으로 검증한 것으로 표현하지 않는다.
본문에서 새 발견·질문·결정을 추출해 메모리로 남길 때는 별도 기록과 해당 보고서 버전·위치를 연결한다.
보고서 전체를 checkpoint로 대체하거나, 본문 모든 문장을 검토된 프로젝트 지식으로 자동 승격하지 않는다.

## 6. 정본과 구현 경계

저장 위치는 [ADR-0006](decisions/0006-common-record-contract.md) 7절로 채택했다. 아직 생성되는 구조는 아니다:

```text
artifacts/reports/<report_id>/
  .staging/<revision_id>/  준비 중인 저장. 저장 시도마다 새로 만들며 버전이 아님
  <revision_id>/
    manifest.json          형식·시각·근거·구성 파일과 해시(analytics.report_revision/1)
    content/               저장한 본문·이미지·첨부 등 보존 바이트
journal.jsonl              보고서 저장의 완료 이벤트(report_revision)와 정정·철회·관계 이벤트
workspace/                 Reports·Visualizations를 포함한 재생성 가능한 분석 인터페이스
```

보고서 본문이 HTML이어도 보존 바이트는 정본에 속한다. `workspace/`를 삭제·재생성해도 이 파일과 버전 기록은 남아야 한다.
기존 작업 파일이나 변경 가능한 `data/derived/` 경로만 링크하는 것으로 본문·첨부 보존을 대신하지 않는다.
첨부 파일 집합을 복사하거나 불변 artifact 참조로 고정하고, 파일별 해시·누락·외부 의존성을 확인한다.
외부 URL은 자동으로 보존된 자료가 아니다. 외부 의존성이 남으면 오프라인 읽기 범위를 표시한다.

쓰기 조정은 관리 파일을 준비·확인하고 보고서 버전 완료를 기록한다. 필요한 파일이 없으면 완료로 표시하지 않는다.
준비 중 원본 파일 집합이 바뀌면 일관된 기준으로 다시 준비하거나 미완료로 남긴다. 나중에 계산한 해시만으로 작성 당시의 일관성을 보장했다고 표시하지 않는다.
작업 중단·부분 파일·완료 이벤트 누락은 불완전 상태로 탐지하고, 같은 등록 요청의 재시도는 기존 완료 결과와 대조한다.
채택한 절차는 시도마다 새 staging에 복사·해시 → journal 잠금을 잡고 `request_id`와 기대한 `previous_revision` 확인 → 이름 바꾸기 → 완료 이벤트 → 잠금 해제다. 확인부터 완료 이벤트까지 한 번의 잠금 안에서 한다.
같은 `request_id`의 재시도는 같은 지문이면 기존 결과를, 다른 지문이면 `request_conflict`를 돌려준다. 이름을 바꾼 뒤 멈춘 저장은 head가 아직 그 `previous_revision`일 때만 완료 이벤트를 더하고, 그사이 다른 저장이 끝났으면 `revision_conflict`로 미완료에 남긴다.
파일 경로는 `content/` 안의 이식 가능한 상대 경로이고 대소문자를 무시하는 파일 시스템에서도 서로 다르다. 어기면 `report_path_invalid`로 거절한다(ADR-0006 7·8절).
본문의 일부만 작성된 중간 보고서와 파일 저장에 실패한 보고서를 구별한다. 부분 분석을 설명하는 정상 보고서는 저장 가능하다.
이 제한된 저장 경계의 검증은 베타에 필요하다. 프로젝트 전체 트랜잭션·임의 생성 코드의 정확히 한 번 실행은 별도 후속 범위다.

[아키텍처](ARCHITECTURE.md)의 공통 기록·ArtifactStore는 정체성·바이트를, 읽기 모델은 목록·관계·검색을 맡는다.
작성·생성은 자유 코드나 기존 실행 경로를 사용한다. 템플릿은 선택 가능한 생성 입력이고, 형식별 미리보기·변환은 별도 adapter다.
WorkspaceRenderer는 보존된 내용을 읽는다. 보고서 목록을 그리는 함수에 생성 코드 실행이나 모델 호출을 넣지 않는다.
새 형식 추가를 위해 지표·journal·Aelix 도구 schema를 형식마다 바꾸지 않는다. 미지원 형식도 메타데이터와 원본 바이트를 잃지 않는다.
새 기록·manifest는 B1의 호환 전환(#13)에 포함한다. 구버전 kit이 무시한 채 쓰지 않게 표식의 가족과 `min_writer_version`으로 막고, 캐시 정리로 삭제하지 않게 한다.

## 7. 토큰과 공유 비용

보고서 생성은 사용자 요청·분석 과제에 포함된 작성 작업이나 명시적으로 설정한 자동화에서 수행한다. 매 실행·매 턴마다 자동 요약 보고서를 만들지 않는다.
등록된 내용의 렌더·목록 조회·build·publish는 기본적으로 추가 LLM 호출 없이 수행한다.
보고서 읽기나 재게시를 위해 원래 분석·생성 코드를 자동 재실행하지 않는다.

에이전트는 먼저 제목·요약·시점·버전·관련 질문·근거 ID를 읽고, 선택한 섹션·파일·컬럼을 요청한다.
모든 보고서 본문·차트 이미지를 기본 프롬프트에 넣지 않는다. 본문 추출 미지원과 내용 없음도 구별한다.
보고서 작성·분석 실행·내용 회수·결정적 렌더의 비용을 나누고 전체 과제 토큰·시간을 함께 측정한다.
토큰 목표는 성능 측정 기준이며 큰 보고서 생성이나 필요한 원문 조회를 금지하는 한도가 아니다.

공유 build는 보고서 버전만 선택하거나 다른 분석 기록과 함께 묶을 수 있다. 게시본에는 포함한 보고서 버전·파일 해시를 기록한다.
선택한 파일뿐 아니라 HTML·그림·첨부 안의 내용에도 공유 범위를 적용한다. 자유 형식 문서의 내용을 메타데이터 필터만으로 제거했다고 간주하지 않는다.
제외할 내용이 본문·이미지에 들어 있으면 수정한 별도 공유용 산출물을 검토하거나 해당 파일을 포함하지 않는다.
가공한 공유용 파일은 원본 보고서 버전·변환·새 해시를 연결하고 원본과 동일하다고 표시하지 않는다.
미포함 근거, 원본 자체의 누락, 미지원 미리보기는 각각 다른 상태로 보인다. 원본 폴더 없는 환경에서 링크·자원이 동작해야 한다.

## 8. 도입 범위와 수용 기준

B1에서 식별자·정확한 참조·호환 전환을 함께 설계하고, B4-r에서 저장·버전·자유 본문·Reports 탐색·반복 묶음을 구현한다.
B4-s의 독립 build·publish에서 선택한 보고서 버전을 공유한다. 모든 문서 변환기·시각 편집기·예약 생성·공동 편집은 첫 베타의 전제조건이 아니다.

| 시나리오 | 통과 증거 |
|---|---|
| 분석 중간에 자유 형식 보고서 저장 | 지표 미정·진행 중인 프로젝트에서 Markdown/HTML 저장 후 분석 계속, 다른 문서 파일은 보존·다운로드 |
| 내용 수정·데이터 교체 | v2 생성 뒤 v1 본문·첨부 해시와 근거 버전 유지, 최신 보기와 과거 인용 구별 |
| 여러 컬럼의 보고서 | 한 문서의 섹션 및 개별 보고서 묶음, 요청한 범위·부분 실패·실패분 추가 후 새 묶음 검증 |
| 탐색·맥락·이력 | 보고서 → 당시 차트/지표/발견 → 같은 보고서 위치로 복귀, 본문을 현재 검증된 발견으로 자동 승격하지 않음 |
| 다시 렌더·등록 재시도 | `workspace/` 재생성에도 원본 유지, LLM/분석 자동 재실행 0회, 불완전 저장 탐지·기존 버전 덮어쓰기 없음 |
| 선택한 보고서 공유 | 원본 없는 환경의 파일·링크, 제외한 내용의 실제 부재, 보고서 버전과 게시 버전의 대응 |

이는 [Q16 보고서 산출물](BETA-QUALITY-GATES.md)의 제안된 검증 범위이며 아직 통과한 결과가 아니다.
